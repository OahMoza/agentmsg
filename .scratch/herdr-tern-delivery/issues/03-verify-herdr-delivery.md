# 03：验证 Herdr 真实投递边界

**Blocked by:** 无。

**What to build:** 用户可以区分 Herdr 适配器的模拟测试结论与实际终端表现，了解通知提交、状态门和审批识别在受测环境中的真实行为。

**Status:** needs-info

- [ ] 在允许的 Herdr 受管环境中、仅针对自行创建的隔离目标，记录客户端和服务端版本与受测 Agent 类型。
- [ ] 验证可构造的空闲、忙碌和已识别审批 / 提问场景：消息状态与实际提交行为相符，审批场景不注入或代答。
- [ ] 验证通知只含固定取信指引及消息 ID，`delivered` 只表示提交已接受；通过信箱取信或回执验证后续阶段。
- [ ] 使用现有单次投递边界验证无法识别、失败和结果不明时的消息状态；覆盖重绑和消息 ID 去重边界，保留认领与 fencing 语义。
- [ ] 实际环境无法建立或某状态无法构造时，记录明确缺口和原因，不以 mock 测试代替真实验证，也不宣称普遍兼容。
- [ ] 不安装或更新集成，不关闭用户的 pane，也不更改既有消息协议。

## 验证记录

- 本次客户端为 Herdr 0.9.5；执行环境没有 `HERDR_ENV=1`，因此按官方 `herdr --skill` 停止控制，服务端版本和目标 Agent 未确认。
- 临时 SQLite 信箱的真实 `watch --once` 在非受管环境拒绝 Herdr 投递，消息保持 `pending`。
- 空闲、忙碌、审批、真实通知及回执仍需在 `HERDR_ENV=1` 的受管 pane 内，以自建隔离 pane 和临时数据库验证；未安装集成或操作用户 pane。
